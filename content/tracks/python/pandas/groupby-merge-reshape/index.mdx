<Section kind="intuition" title="Most analysis is three verbs">

Look at almost any analysis notebook and you find the same three moves. **Group**: total sales per region,
average rating per product. **Join**: attach each order’s user plan from another table. **Reshape**: turn one
row per store-and-month into a table with a column per month, or back.

pandas has one tool for each: `groupby`, `merge` and `pivot_table`/`melt`. They are short to write and easy to
get subtly wrong: a join that silently duplicates rows, a group total that silently drops missing keys. This
lesson shows the shape of each result, so you can predict it before you run it.

</Section>

<Section kind="technical" title="groupby, merge and reshape">

**Split-apply-combine.** `df.groupby(key)[col].op()` splits rows by `key`, applies `op` to each group’s `col`,
and combines the answers (<Term id="split-apply-combine">split-apply-combine</Term>,
<Term id="group-by">group by</Term>). The kind of `op` decides the shape:

- An **aggregation** (`sum`, `mean`, `size`, `count`, `min`, `agg([...])`) gives **one row per group**, indexed
  by the key (sorted). `count` skips NaN values; `size` counts rows.
- A **transform** (`transform("sum")`, `cumsum`, `rank`, `shift`) gives **one value per original row**, in the
  original order, which is how you add "share of my group’s total" as a column.
- `filter(lambda g: ...)` keeps or drops whole groups.

Group by several keys with a list, and name outputs with `agg(total=("sales", "sum"))`. Rows with a missing key
are dropped unless you pass `dropna=False`.

**Merge.** `left.merge(right, on="key", how=...)` matches rows by key values, as an SQL join does
(<Term id="sql-join">join</Term>): `inner` keeps matches, `left` keeps every left row (NaN where no match), `outer`
keeps everything. Each duplicate key on one side **multiplies** the matching rows on the other. Guard every
merge with `validate="many_to_one"` (or `one_to_one`), which raises `MergeError` when keys are not unique, and
use `indicator=True` to see which rows matched.

**Reshape.** In <Term id="long-format">long format</Term> each row is one observation (store, month, sales);
wide format has a column per month. `pivot_table(index, columns, values, aggfunc)` goes long to wide, aggregating
duplicates; `melt(id_vars, var_name, value_name)` goes wide to long. Plotting libraries and `groupby` usually want
long format.

</Section>

<Section kind="mistakes" title="Joins and groups that lie">

<CommonMistake
  title="A many-to-many merge"
  wrong={'orders.merge(users, on="user_id")   # users has a duplicated id'}
  error="No error: the result has more rows than orders, and every sum over it is inflated."
  cause="Each duplicate key multiplies the matching rows."
  fix={'orders.merge(users, on="user_id", how="left", validate="many_to_one")'}
/>

<CommonMistake
  title="Losing rows with missing keys"
  wrong={'df.groupby("region")["amount"].sum().sum()   # smaller than df["amount"].sum()'}
  error="No error: rows whose region is NaN are silently left out."
  cause="groupby drops missing keys by default."
  fix={'df.groupby("region", dropna=False)["amount"].sum()'}
/>

<CommonMistake
  title="pivot with duplicate entries"
  wrong={'long.pivot(index="store", columns="month", values="sales")'}
  error="ValueError: Index contains duplicate entries, cannot reshape"
  cause="pivot cannot decide which of two values for (B, feb) to keep."
  fix={'long.pivot_table(index="store", columns="month", values="sales", aggfunc="sum")'}
/>

</Section>

<Section kind="practice" title="Where you will meet it">

| In data and ML code | What it builds |
|---|---|
| `df.groupby("user_id")["amount"].agg(["sum", "count"])` | Per-user features for a model |
| `df["user_mean"] = df.groupby("user_id")["x"].transform("mean")` | A group statistic on every row |
| `events.merge(users, on="user_id", how="left", validate="many_to_one")` | Enrich events safely |
| `metrics.pivot_table(index="epoch", columns="split", values="loss")` | Train and validation loss side by side |
| `wide.melt(id_vars="run")` | Long format for plotting many runs |

<Section kind="summary">

- Aggregations give one row per group; transforms give one value per row, in the original order.
- Merges multiply rows on duplicate keys: always pass `validate`, and check row counts.
- `groupby` drops missing keys unless `dropna=False`.
- `pivot_table` goes long to wide (aggregating duplicates); `melt` goes wide to long.
