<Section kind="intuition" title="Cleaning is a series of decisions">

Raw data arrives with gaps, repeats and values in the wrong type: `"1,250.00"` as text, `"n/a"` in an age
column, February 30th, the same user twice. None of these raise an error on load. They show up later as a mean
that is slightly off or a model that quietly learns from duplicates.

Cleaning is not a single function call. It is a short list of decisions, each of which changes the data:
what counts as missing, which row of a duplicate to keep, how to fill a gap. Good cleaning code makes every
decision visible, counts what it changed, and fails loudly when the data breaks a rule.

</Section>

<Section kind="technical" title="Audit, coerce, deduplicate, fill, validate">

**Audit first.** Before changing anything, look: `df.shape`, `df.dtypes` (a numeric column read as `str`
means some value is not a number), `df.isna().sum()`, `df.duplicated().sum()` (whole-row duplicates),
`df[key].duplicated().sum()` (key duplicates), `describe()` for impossible ranges, and `value_counts()` on text
columns for spelling variants.

**Coerce types.** `pd.to_numeric(col, errors="coerce")` and `pd.to_datetime(col, errors="coerce",
format=...)` convert what they can and turn the rest into NaN or NaT. They never complain, so compare missing
counts before and after: the difference is the number of parse failures. Clean the text first where the fix is
known (remove thousands separators), and treat impossible values (age 230, a negative fee) as missing with
`where`.

**Duplicates.** `drop_duplicates()` removes rows identical in every column. When a key should be unique,
decide which row wins: usually the latest, by sorting with `sort_values("updated")` and then calling
`drop_duplicates(subset="user_id", keep="last")`.

**Missing values.** Ask why a value is missing before choosing (<Term id="missing-value">missing value</Term>).
Dropping rows is simple but discards their other columns and can bias the sample. Filling
(<Term id="imputation">imputation</Term>) with the median is robust to outliers; the mean is not; a constant
such as 0 is right only when it is the true meaning ("no purchases"). For a model, add a
<Term id="missingness-indicator">missingness indicator</Term> so the fact that a value was missing is not lost.
In an ML pipeline, compute fill statistics on the training split only.

**Validate.** End with assertions about what must be true (<Term id="data-validation">data validation</Term>):
unique keys, ranges, allowed categories, no missing labels. A failed assertion stops the pipeline with a
message, which is far cheaper than a wrong number in a report.

</Section>

<CommonMistake
  title="Filling with statistics from all the data"
  wrong={'df["income"] = df["income"].fillna(df["income"].median())\ntrain, test = split(df)'}
  error="No error: the test rows helped choose the fill value (leakage)."
  cause="The median was computed before splitting."
  fix={'train, test = split(df)\nfill = train["income"].median()\ntrain["income"] = train["income"].fillna(fill)\ntest["income"] = test["income"].fillna(fill)'}
/>

<CommonMistake
  title="Comparing with None"
  wrong={'df[df["income"] == None]'}
  error="No error: the result is empty."
  cause="Missing values are NaN, and comparisons with NaN are always False."
  fix={'df[df["income"].isna()]'}

<Section kind="practice" title="Where you will meet it">

| In data and ML code | What it does |
|---|---|
| `df.isna().mean().sort_values()` | Share of missing values per column |
| `pd.to_numeric(col, errors="coerce")` | Parse numbers, count failures |
| `drop_duplicates(subset=key, keep="last")` | One row per key, newest wins |
| `SimpleImputer(strategy="median", add_indicator=True)` | scikit-learn’s fill-plus-flag, fitted on train |
| `assert df[key].is_unique` | A cheap validation gate |

<Section kind="summary">

- Audit before you change anything: dtypes, missing counts, whole-row and key duplicates, ranges.
- Coerce with `errors="coerce"` and count the NaN it created; turn impossible values into missing ones.
- Choose a missing-value policy on purpose: the median resists outliers, dropping loses other columns, and a flag
  keeps the signal.
- End every cleaning step with assertions.
