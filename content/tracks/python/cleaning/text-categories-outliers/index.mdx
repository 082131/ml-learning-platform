<Section kind="intuition" title="Same thing, many spellings; rare thing, real or wrong?">

People type `New York`, `new york ` and `NYC` for one city. Product codes hide a number inside free text. A
plan column has `Pro`, `pro ` and `PRO`. Until they are unified, every count and group is split across spellings.

Numbers have their own version of the problem: a few values far from the rest. Some are errors (a duration of
95 minutes because a timer was left running), some are the most interesting rows in the table. Cleaning has to
**find** them reliably and then **decide** what they are, and the second part is not a formula.

</Section>

<Section kind="technical" title="Text, categories and outliers">

**Text.** The `.str` accessor applies string methods to every value and passes missing values through:
`strip`, `lower`, `replace`, `contains`, `startswith`, `split`, `len`. Normalize in a fixed order: strip
whitespace, lowercase, remove punctuation, then unify known aliases with an explicit dictionary.

**Regular expressions.** A <Term id="regular-expression">regular expression</Term> describes a text pattern:
`\d+` one or more digits, `\s` whitespace, `\w` a letter, digit or underscore, `[-\s]?` an optional hyphen or
space, `(...)` a group to capture, `(?i)` ignore case. `s.str.extract(pattern)` returns one column per captured
group, with NaN where the pattern does not match; `s.str.contains(pattern)` gives a mask. Write the raw string
form, `r"\d+"`, so Python does not interpret the backslashes.

**Categories.** Map spellings to a fixed set with `s.map(table)`, which turns anything not in the table into NaN,
and then **report** the unmapped values instead of letting them vanish. `replace` leaves unknown values as they
were, which hides new spellings. Finish with a categorical dtype listing the allowed values.

**Outliers.** An <Term id="outlier">outlier</Term> rule flags values; it does not judge them. Three common
rules:

- **IQR rule**: outside $[Q_1 - k \cdot \mathrm{IQR},\ Q_3 + k \cdot \mathrm{IQR}]$, where
  $\mathrm{IQR} = Q_3 - Q_1$ (<Term id="interquartile-range">interquartile range</Term>) and $k$ is 1.5 or 3.
  Quartiles ignore the extremes, so the rule is robust.
- **z-score**: $|x - \bar x| / s > 3$ (<Term id="z-score">z-score</Term>). Simple, but the mean and standard
  deviation include the outliers, which can hide them (masking), especially in small samples.
- **Robust z**: $0.6745\,(x - \text{median}) / \text{MAD} > 3.5$, using the median absolute deviation.

**Then decide.** Impossible values (a negative age, a heart rate of 0) are errors: set them to missing. Possible
but extreme values are data: keep them, and if a method is sensitive to them, cap with `clip` at chosen
percentiles (winsorizing) or use a robust statistic. Never drop rows only because a rule flagged them.

</Section>

<CommonMistake
  title="Matching a regex as plain text"
  wrong={'codes.str.replace(".", "")'}
  error="No error in pandas 3: the dot is matched literally, because regex defaults to False."
  cause="Older code relied on regex=True by default; be explicit either way."
  fix={'codes.str.replace(r"[^\\w\\s]", "", regex=True)   # remove punctuation'}
/>

<CommonMistake
  title="replace that hides new spellings"
  wrong={'plan = plan.replace({"Pro": "pro", "Free": "free"})'}
  error="No error: 'PRO ', 'trial' and every future variant pass through untouched."
  cause="replace leaves unknown values alone."
  fix={'mapped = plan.str.strip().str.lower().map(table)\nassert mapped.notna().all(), plan[mapped.isna()].unique()'}

<Section kind="summary">

- Normalize text in a fixed order (strip, lowercase, punctuation, aliases) with the `.str` accessor.
- `str.extract` with a raw-string regex pulls fields out of free text; non-matches become NaN.
- Map categories with `map` and report unmapped values instead of hiding them.
- IQR and robust z resist masking; the plain z-score can miss outliers. Flag, inspect, then fix errors and keep
  real extremes.
