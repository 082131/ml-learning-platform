<Section kind="intuition" title="The whole course on one table">

Real work rarely arrives as a clean tensor. It arrives as an export with odd labels, placeholders and copies, and
someone asks a plain question: who leaves, and can we see it coming? This project walks that whole path with the
tools from every chapter: pandas to profile and clean, tests and validation checks to trust the result, NumPy and
the statistics chapter to answer questions with honest uncertainty, and PyTorch to build a model and prove it
beats a <Term id="baseline-model">baseline</Term>.

The data is generated by a seeded script, so you also get something real projects never give you: the truth.
You know how churn was produced, so you can check whether your analysis and model recovered it.

</Section>

<Section kind="technical" title="What to build">

**The data.** `starter.py` builds 2,000 customers and exports 2,040 rows, because 40 are exact duplicates. Churn
depends on support tickets (up), sessions in the last 30 days (down), tenure (down) and the basic plan (up).
Then the export goes wrong: about 15% of plan labels are upper-cased with a trailing space, fees are text like
`$12.00`, some fees are `n/a`, `sessions_30d` uses `-1` for "not tracked", some ages are `999` or missing.

**Cleaning** is a function, `clean_customers(raw) -> DataFrame`, in its own module with tests, so you can run it
again on next month’s export. **Validation** (<Term id="data-validation">data validation</Term>) is a set of checks
that raise when an assumption breaks, run after every cleaning.

**Analysis** answers two questions with a chart each, and puts a bootstrap interval on the main difference.
**Modeling** splits 60/20/20, fits every preprocessing statistic on the training rows, trains two PyTorch models
with the loop from the previous lesson, and compares them with a constant baseline on log loss and ROC AUC.

**Reference numbers.** A complete solution (NumPy 2.5.3, pandas 3.1.1, PyTorch 2.14.1 on CPU) got these. Yours
will differ in the decimals if you split or impute differently, but should be close:

| Step | Reference result |
|---|---|
| After cleaning | 2,000 rows; 78 sessions and 129 ages missing (including the impossible ones) |
| Churn rate by plan | basic 0.295 (1,013 customers), pro 0.113 (689), team 0.121 (298) |
| Basic minus pro | 0.182, 95% bootstrap interval [0.145, 0.219] |
| Baseline, validation | log loss 0.531, accuracy 0.777 (it predicts "no churn" for everyone) |
| Logistic regression, validation | log loss 0.430, AUC 0.795 |
| MLP (32 hidden units), validation | log loss 0.430, AUC 0.798 |
| Both, test (used once) | AUC 0.828 |

The MLP does not beat logistic regression. That is the expected result here, because churn was generated from a
linear logit, and it is exactly the kind of finding the report should state plainly.

<Callout kind="simplification">
  Generated data keeps the project self-contained and checkable, but it is cleaner than reality: the churn rule is
  simple and stable over time, and nothing about the customers changes after the export. With real data, also
  check for time-based leakage (features measured after the churn date) and split by time, not at random.
</Callout>

</Section>

<CommonMistake
  title="Dropping every row with a missing value"
  wrong={'df = clean_customers(raw).dropna()'}
  error="No error: 2,000 customers silently become 1,798."
  cause="Rows with a missing age or untracked sessions are not random: dropping them changes who is in the analysis."
  fix={'df["age_missing"] = df["age"].isna()\ndf["age"] = df["age"].fillna(train_median_age)   # median from training rows only'}
/>

<CommonMistake
  title="Reading -1 as a number of sessions"
  wrong={'df["sessions_30d"].mean()   # with the -1 sentinels still in'}
  error="No error: the mean is pulled down, and the model learns that -1 sessions is a level of activity."
  cause="A sentinel is a missing value in disguise; pandas cannot know that -1 means 'not tracked'."
  fix={'missing = df["sessions_30d"].eq(-1)\ndf["sessions_missing"] = missing\ndf["sessions_30d"] = df["sessions_30d"].mask(missing)'}
/>

<CommonMistake
  title="Choosing the model on the test set"
  wrong={'for model in candidates:\n    print(model, evaluate(model, X_test, y_test))   # then pick the best'}
  error="No error: the reported test score is the best of several noisy scores, so it is optimistic."
  cause="Once the test set chooses, it is no longer an unseen-data estimate."
  fix={'best = min(candidates, key=lambda m: evaluate(m, X_val, y_val))\nprint(evaluate(best, X_test, y_test))   # once'}
