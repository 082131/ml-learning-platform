<Section kind="intuition" title="Data with its own behavior">

Sooner or later a dict of settings or a pair of lists stops being enough. You want one object that holds a
dataset’s rows **and** knows how many it has and how to hand out row `i`; or a training configuration that checks
its own learning rate.

A <Term id="python-class">class</Term> bundles data with the functions that act on it. Python’s data model goes
one step further: if your class defines a few specially named methods, the built-in syntax works on it.
`len(ds)`, `ds[3]` and `for x in ds` call your code. That is exactly how PyTorch’s `Dataset` works, so this
lesson ends there.

</Section>

<Section kind="technical" title="Classes, instances and the data model">

**Defining and creating.** `class Readings:` defines a class. Calling it, `Readings("kitchen", [21.5, 22.0])`,
creates an *instance* and runs `__init__(self, name, values)` on it, where `self` is the new object.
`self.name = name` creates an *instance attribute*: each object has its own. Names assigned directly in the class
body are *class attributes*, shared by all instances.

**Methods.** A function defined in the class body is a method. `kitchen.mean()` is shorthand for
`Readings.mean(kitchen)`: Python passes the instance as the first argument, which is why every method starts with
`self`.

**<Term id="dunder-method">Dunder methods</Term>.** Python translates syntax into calls of double-underscore
methods:

| You write | Python calls |
|---|---|
| `len(x)` | `x.__len__()` |
| `x[i]` | `x.__getitem__(i)` |
| `v in x` | `x.__contains__(v)` |
| `print(x)`, the console | `x.__repr__()` (or `__str__` for print, if defined) |
| `x == y` | `x.__eq__(y)` |
| `for v in x` | `x.__iter__()`, or `__getitem__(0)`, `(1)`, … until `IndexError` |

**<Term id="dataclass">Dataclasses</Term>.** For classes that are mostly fields, `@dataclass` writes
`__init__`, `__repr__` and `__eq__` from annotated class attributes. Fields with defaults must come after fields
without. A mutable default needs `field(default_factory=list)`, so each instance gets its own list.
`__post_init__` runs after the generated `__init__`, which is the place for validation. `frozen=True` makes
instances read-only, and `dataclasses.asdict` turns one into a dict, handy for logging a run’s configuration.

**Inheritance, briefly.** `class PairsDataset(Dataset):` inherits from `Dataset`. Your class gets the parent’s
methods and overrides the ones it defines. `super().__init__()` runs the parent’s `__init__`; PyTorch modules
need that call, as you will see in the PyTorch chapter.

</Section>

<Section kind="mistakes" title="Class pitfalls">

<CommonMistake
  title="Forgetting self"
  wrong={'class Readings:\n    def mean():\n        return sum(self.values) / len(self.values)\n\nReadings().mean()'}
  error="TypeError: Readings.mean() takes 0 positional arguments but 1 was given"
  cause="Python always passes the instance as the first argument of a method call."
  fix={'    def mean(self):'}
/>

<CommonMistake
  title="A mutable dataclass default"
  wrong={'@dataclass\nclass Batch:\n    items: list = []'}
  error="ValueError: mutable default <class 'list'> for field items is not allowed: use default_factory"
  cause="One list would be shared by every instance; dataclasses refuse it when the class is defined."
  fix={'    items: list = field(default_factory=list)'}
/>

<CommonMistake
  title="Not calling the parent’s __init__"
  wrong={'class Net(nn.Module):\n    def __init__(self):\n        self.layer = nn.Linear(2, 1)'}
  error="AttributeError: cannot assign module before Module.__init__() call"
  cause="nn.Module sets up its registry of layers in its own __init__, which never ran."
  fix={'    def __init__(self):\n        super().__init__()\n        self.layer = nn.Linear(2, 1)'}
/>

<Section kind="summary">

- A class bundles attributes and methods; calling it runs `__init__` with `self` as the new instance.
- Dunder methods connect your class to Python syntax: `__len__`, `__getitem__`, `__contains__`, `__repr__`,
  `__eq__`.
- `@dataclass` writes the boilerplate for field-holding classes; use `default_factory` for mutable defaults and
  `__post_init__` for validation.
- A PyTorch map-style `Dataset` is just `__len__` plus `__getitem__`.
