<Section kind="intuition" title="Three ways to pack lighter">

Suppose you must fit a library into a smaller room. You can print every book in smaller type (it all stays, each
page is a little harder to read). You can tear out the pages nobody reads (less paper, but only if you knew which
pages those were). Or you can have an expert write a short summary of the whole library (a new, smaller book that
captures what matters, which takes real work to write).

These are the three main ways to shrink a trained model. <Term id="quantization">Quantization</Term> stores every
weight with fewer bits. <Term id="pruning">Pruning</Term> removes weights. <Term id="knowledge-distillation">Distillation</Term>
trains a smaller model to imitate the big one. Each removes something different, costs something different to
apply, and saves memory or time only under certain conditions.

</Section>

<Section kind="technical" title="What each method removes, and when it pays">

**Quantization** keeps every weight and lowers its precision, as the
[precision lesson](#/learn/inference/precision/precision-quantization) showed. It needs no training (post-training
quantization) or a short fine-tune (quantization-aware training). It cuts weight memory directly, and speeds up
memory-bound layers because fewer bytes are read; integer kernels can speed up the arithmetic too.

**Magnitude pruning** sets the weights with the smallest absolute values to zero, on the theory that they change
the output least. With a per-layer threshold every matrix loses the same share; a global threshold lets layers
with many small weights lose more. After pruning, a short fine-tune usually recovers some accuracy.

The catch is that zeros in a dense matrix still cost memory and time. A dense kernel multiplies them like any
other number. Savings need either a <Term id="sparse-matrix">sparse format</Term>, which stores values and their
positions and only beats dense below about 50% nonzeros, or sparse hardware (NVIDIA's 2:4 pattern: two zeros in
every group of four), or **structured pruning**, which removes whole neurons, channels or attention heads so the
matrices themselves get smaller.

**Distillation** trains a new, smaller student to match the teacher's outputs. The teacher's probabilities are
softened with a <Term id="softmax-temperature">temperature</Term> $T$:

$$
p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}
$$

At $T = 1$ the teacher says test image 0 is a 7 with probability 0.989. At $T = 4$ it says 7: 0.600, 9: 0.194:
this 7 looks a little like a 9, which a one-hot label cannot say. The student minimizes the KL divergence to these
soft targets (times $T^2$), usually mixed with the ordinary loss on the labels. Distillation costs a full training
run, but the student can have any architecture, so it saves memory and time everywhere, and the teacher can label
data that has no labels.

**On the digits model** (349 of 360 right in float32, 1,184 weights in W1 and W2):

| Method | Result | Weight memory | Faster? | Cost to apply |
| --- | --- | --- | --- | --- |
| INT8, symmetric per tensor | 349 of 360 | ÷4 | yes, if memory-bound or with integer kernels | none (minutes) |
| INT4, per channel | 345 of 360 | ÷8 | yes, if memory-bound | none |
| Magnitude pruning, 50% global | 338 of 360 | unchanged if stored dense | no, with dense kernels | none, plus optional fine-tune |
| Distilled 64 → 8 → 10 student | 344.0 mean of 5 seeds | ÷2 | yes, everywhere | a training run |

<Callout kind="simplification">
  A 1,210-parameter model on 360 test images is a teaching example. Large networks tolerate much more pruning and
  quantization, because they have more redundancy, and published results for them use fine-tuning after pruning.
  The ranking of costs and the conditions for real speedups carry over; the exact percentages do not.
</Callout>

</Section>

<Section kind="mistakes" title="Compression mistakes">

<CommonMistake
  title="Expecting unstructured sparsity to be faster"
  wrong={'W = magnitude_prune(W, 0.9)   # 90% zeros\ny = x @ W.T                   # same dense matmul'}
  error="No error. Latency and memory are unchanged: the dense kernel multiplies the zeros too."
  cause="Dense kernels do not skip zeros, and a dense array stores them."
  fix={'# Either remove whole rows or channels (structured pruning), so W itself is smaller,\n# or use a sparse format and kernels, or hardware sparsity (2:4), and measure the speedup.'}
/>

<CommonMistake
  title="Judging compression on the training data"
  wrong={'acc = (predict(P1, P2, X_train) == y_train).mean()   # looks fine at 80% sparsity'}
  error="No error. The number is optimistic: it measures how well the pruned model remembers data it was fit to."
  cause="Compression can remove what made the model generalize while keeping what it memorized."
  fix={'acc = (predict(P1, P2, X_test) == y_test).mean()     # held-out data, never used for training'}
/>

<Callout kind="warning">
  Measure what compression changes per slice, not only overall. A model can keep its average accuracy while losing
  most of it on one rare class. Compare the confusion matrix before and after, as in
  [error analysis](#/learn/ml/practice/ablations).
</Callout>

</Section>

<Section kind="practice" title="Choosing a method">

Start from the constraint and the budget you have to apply the method:

1. **The weights do not fit, or decoding is memory-bound.** Quantize the weights first: INT8 or 4-bit formats with
   per-channel or per-group scales. No training needed; check accuracy on a held-out set.
2. **The model fits but is too slow on compute-bound layers.** Use INT8 or FP8 kernels if the hardware has them;
   consider structured pruning (remove heads or channels) with a fine-tune.
3. **You need a much smaller or different architecture**, for example to run on a phone. Distill: it costs a
   training run, but the student can be any shape, and unlabeled data becomes training data.
4. **Combine them.** A distilled student can then be quantized. Measure each step separately so you know what each
   one cost.

Whatever you choose, write down the accuracy tolerance before you start, measure on held-out data, and measure
the latency and memory on the target hardware: compression that does not speed anything up is not worth its
accuracy loss.

</Section>

<Section kind="summary">

- Quantization lowers precision, pruning removes weights, distillation trains a smaller model.
- Quantization is cheap and saves memory directly; unstructured pruning saves nothing without sparse formats,
  kernels or hardware; structured pruning and distillation shrink the actual computation.
- Magnitude beats random pruning by a wide margin; global thresholds protect small layers.
- Soft targets at temperature $T$ carry the teacher's view of similar classes, and let unlabeled data train the
  student.
- Measure accuracy on held-out data and speed on the target hardware, for each step.
