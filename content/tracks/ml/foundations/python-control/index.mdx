<Section kind="intuition" title="Programs that decide and repeat">

The programs so far ran every line once, top to bottom. Real programs make decisions ("did this student pass?")
and repeat work ("for every student..."). Python has three tools for that:

- A <Term id="python-function">function</Term> packages a few lines under a name, so you can run them again with
  different inputs: `grade(72, 60)`.
- A **condition** (`if`) runs a block only when a comparison is True.
- A <Term id="loop">loop</Term> runs a block again and again: `for` once per item, `while` as long as a condition
  holds.

Training a model is exactly this shape: a loop over the data, a function that computes the error of one example,
and conditions that decide when to stop.

</Section>

<Section kind="technical" title="def, if, for and while">

**Functions.** `def grade(score, pass_mark):` defines a function with two parameters. Calling `grade(72, 60)` runs
its body with `score = 72` and `pass_mark = 60`. `return` ends the function and hands a value back; the call
`grade(72, 60)` is then replaced by that value. A function without `return` gives back `None`.

**Conditions.** Comparisons give a bool: `72 >= 60` is `True`. The operators are `==` (equal), `!=` (not equal),
`<`, `<=`, `>`, `>=`. Combine them with `and`, `or`, `not`. `if` can be followed by any number of `elif` branches
and one `else`; Python runs the first branch whose condition is True and skips the rest.

**Blocks.** A colon at the end of a line opens a block, and the block is every following line indented further
(four spaces by convention). Indentation is not decoration in Python: it decides which lines belong to the `if`,
the loop or the function.

**for loops.** `for s in scores:` runs its block once per item, with `s` naming the item. `range(n)` produces the
numbers $0, 1, \dots, n-1$, so `for i in range(4)` runs 4 times. After the loop ends, the loop variable keeps its
last value.

**while loops.** `while balance < 150:` checks the condition before every pass and stops when it is False. If
nothing in the body ever makes the condition False, the loop never ends; in this site's runner, a program that
runs longer than 10 seconds is stopped.

</Section>

<Section kind="mistakes" title="Indentation, = in a condition, and a missing return">

<CommonMistake
  title="Forgetting to indent a block"
  wrong={'def grade(score):\nif score >= 60:\n    return "pass"'}
  error="IndentationError: expected an indented block after function definition on line 1"
  cause="The colon after def opens a block, so the next line must be indented further. Python reads the if as outside the function, which leaves the function empty."
  fix={'def grade(score):\n    if score >= 60:\n        return "pass"'}
/>

<CommonMistake
  title="Using = instead of == in a condition"
  wrong={'score = 70\nif score = 60:\n    print("pass")'}
  error="SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?"
  cause="One = assigns a value; it cannot appear where Python expects a True/False condition. Python points at it and suggests ==."
  fix={'if score == 60:\n    print("pass")'}
/>

<Callout kind="warning">
  A function without `return` raises no error: it returns `None`. If `total(xs)` adds up its numbers into `s` but
  never says `return s`, `print(total([1, 2, 3]))` prints `None`. When a function's result is `None`, look for a
  missing `return`, or a `return` that is indented into a loop and runs too early.
</Callout>

</Section>

<Section kind="summary">

- `def` defines a function; `return` hands a value back, and without it the result is `None`.
- `if` / `elif` / `else` run the first branch whose condition is True. `=` assigns, `==` compares.
- `for x in items:` repeats once per item; `range(n)` gives $0 \dots n-1$. `while` repeats until its condition
  is False.
- Indentation decides what belongs to each block.
